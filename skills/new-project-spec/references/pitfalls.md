# 「环境与已知坑」怎么写

这一节是 AGENTS.md 里最容易被写坏的部分：要么空着，要么把某台机器的偶然事实写成项目真理，换台机器就把人带偏。

## 写法规约

**每条坑五段式**，缺一条下次就认不出来：

1. **症状**——观察到什么（现象描述，不是原因）。写得具体到能被搜索：报错原文、屏上表现、数字跳动范围。
2. **根因**——为什么（一句话讲清机制，越反直觉越要写）。
3. **修法**——照做能解决的步骤；有多个候选时按「先轻后重」排序。
4. **⚠️ 不稳定的地方**——修法失效的条件与退路（如「该重定向并不稳定，可靠做法是多轮全量 + 补跑」）。
5. **判据**——怎么确认这次是不是同一个坑（一条命令、一个返回码、一个字段），以及**怎么确认它已经不在了**。

**通用 vs 本机，必须分开标注**：

- 不带标记的条目 = 仓库属性，任何机器、任何 agent、CI 上都成立，可以照做。
- `〔本机〕` 前缀 = 绑定某台机器的系统环境（代理、终端代码页、凭据助手、安全软件）。**必须在同一条里写明「换机器或 CI 上不适用，不要照搬」**。
- 文件头再来一行总述：`> 标 〔本机〕 的条目与本机的系统环境绑定，换机器不适用；其余是仓库属性，任何环境都成立。`

**反直觉优先**：坑的价值在于「按常理推断会做错」。所以每条都要点出那个误导性的直觉——例如「`os.path.exists('…\\nul')` 恒为 True，别用它判断」，比只写「别用 `> nul`」有用得多。

## 新仓库第一天该写什么

只写**写法规约 + 已经踩到的坑**。不要硬凑条目：一份塞满「常见问题」的 AGENTS.md 会让人不再相信它。积累来源：

- 每次排查耗时超过 10 分钟的问题，收尾时补一条；
- 每次「代码看着对、跑起来不对」的误判；
- 每次 CI 与本地行为不一致。

## 通用坑目录（跨项目常见，可直接抄进新仓库）

以下几条不依赖特定机器，多数 Windows + Node + Git Bash 环境都会遇到：

### POSIX shell 里用 `> nul` 会建出真实文件

- 症状：仓库根莫名出现名为 `nul` 的文件；后续任何操作碰它都报错。
- 根因：`nul`/`con`/`aux`/`prn`/`com1`~`com9`/`lpt1`~`lpt9` 是 Windows 保留设备名，cmd 认，**Git Bash 不认**，于是按普通文件名创建。
- 修法：`> /dev/null`（含 stderr 用 `> /dev/null 2>&1`）；cmd 用 `> NUL`；PowerShell 用 `> $null`。要留报告就用工具自带参数（`--reporter=json --outputFile=…`），别靠重定向。
- ⚠️ 这类文件**建出来可能删不掉**（多种删除路径全部失败，本机脱离沙箱后同样失败，拦截来源未确证）——**预防是唯一可靠策略**。
- 判据：`os.path.exists('<仓库>\\nul')` **恒为 True**（裸路径被解析成设备名），别用它；只有「目录列举里有没有这一项」与「`GetFileAttributesW('\\?\<绝对路径>\nul')` 是否返回 `err=3`」两条可靠。
- 兜底：`.gitignore` 里把这些保留名逐个列出，避免误入提交。

### 控制台中文乱码 ≠ 文件被写坏

- 症状：终端里中文显示成 `???` / ``。
- 根因：编码不匹配——控制台代码页是 936(GB2312)，而 git / node 等原生工具输出 UTF-8。
- 修法：命令开头加 `$OutputEncoding=[Text.Encoding]::UTF8; [Console]::OutputEncoding=[Text.Encoding]::UTF8`（**仅在确认有此问题的环境**，本就是 UTF-8 的控制台不需要，别无条件套用）。
- 关键认知：**乱码只影响终端显示，不会污染代码或提交内容**。写文件一律用编辑工具，不用 shell。别因为看到乱码就去「修」文件。
- 派生坑：**涉及中文内容的校验，不要相信控制台渲染**。`Get-Content | ConvertFrom-Json` 会因字节被改写直接报解析错；`git show | Select-String` 会把相邻两行显示成一行（曾据此误判 CSS 注释吞掉了声明）。校验中文一律用 `node -e` 读原始字节并打印码点。

### 端口漂移把开发服务器与后端服务撞在同一端口

- 症状：默认端口被占时，dev server 自动跳到下一个端口——而那个端口正好是本地后端/代理目标，代理指向自身形成回环，表现为登录或接口请求异常。
- 修法：起服务前先查占用（`netstat -ano | findstr :<端口>`），先停旧实例再启动；**不要让它漂移**。验证完把自己临时起的进程停掉。
- 判据：报错像「后端挂了」但后端进程其实活着 → 先看两边端口是不是撞了。

### HMR 陈旧模块导致「改了不生效」的误判

- 症状：大规模重构/删文件后白屏、样式改了不生效、事件监听指向旧实例。
- 根因：dev server 内存里还挂着旧模块；画布类库（多 stage 实例）在同一浏览器标签里会被污染。
- 修法（**先轻后重，不要急着改代码**）：① 重启 dev server + 浏览器硬刷新，再判断；② 仍异常清构建缓存目录（如 `node_modules/.vite`）再重启；③ 仍报模块找不到才怀疑依赖链接损坏、走重装。
- ⚠️ **必须开全新标签页**：同一标签经历多次 HMR 后会有污染，导致「功能实际正常但就是看着不生效」的误判。

### 测试运行被沙箱提前掐断，汇总数字不可信

- 症状：末尾汇总出现 `Errors`（形如 `EPERM: … open '<临时目录>/…'`），同时 `Test Files` / `Tests` 比真实值少——**少跑的文件不报失败**，只看绿灯会漏。
- 修法：把 `TEMP`/`TMP` 重定向到可写目录后重跑。
- ⚠️ 重定向可能并不稳定（该目录自身仍可能被管控）。可靠做法是多轮全量 + 补跑漏掉的文件，直到逐文件列表与磁盘清单一致。
- 判据：汇总行有 `Errors` 即视为本次不可信；用 `--reporter=verbose` 重跑并与 `find … -name "*.test.ts"` 的结果逐文件比对。**写进变更日志的「实测用例数」必须来自完整运行。**

### 包管理器拦截依赖构建脚本

- 症状：`install` 成功但运行时报缺模块 / 二进制没编译。
- 修法：在 workspace 配置里加构建脚本白名单（如 `esbuild`、`@parcel/watcher`、`vue-demi`），**不要删这份白名单**。

### node_modules 链接损坏

- 症状：`install` 报 "Already up to date"，但运行时 `Cannot find module .../vite/...`。
- 修法：删除 `node_modules` 重新 install。先按上一节排除 HMR 缓存因素，别一上来就重装。

### 网络受限导致 git 推送失败

- 症状：`SSL_ERROR_SYSCALL`（目标域名被网络重置）。
- 修法：走本地代理单次推送（`git -c http.proxy=http://127.0.0.1:<代理端口> push origin <分支>`，端口以实际环境为准）。
- ⚠️ **失败不重试**：连续多次重试既耗时又可能触发网络风控。提交留在本地，等一段时间再试或留到下次。

### 凭据助手反复弹窗

- 症状：git 每次取凭据都弹「选择凭据助手」，勾了「Always use this」也照弹。
- 根因：`credential.helper` 是**多值**键，按 `system → global → local` 依次尝试直到拿到用户名+密码；**取空值会清空此前累积的列表**。某些发行版在 system 级写死了选择器程序，而 UI 的选择只会**追加**到 global，于是列表成了 `[选择器, manager]`——弹窗程序排第一位，每次都先调用它。「默认选中项」那类设置**不能阻止弹窗**。
- 修法：在 user 级配置里**先写一条空值、再写期望的 helper**（顺序不能反，反了会把期望的 helper 一起清掉，变成完全没有 helper）。
